# N5.1 — Production Compose overlay

Short operator note for the production Docker path. Full customer handoff docs come in later N5 gates.

## Files

- Base: `docker/docker-compose.yml`
- Overlay: `docker/docker-compose.prod.yml` (uses Compose `ports: !override` so isolated ports replace base ports instead of appending)
- Frontend nginx proxies `/api/` → `backend:8080` (matches production `apiBaseUrl: '/api/v1'`)

## Run (isolated from local dev stack)

Uses project `project-analytics-prod`, containers `pa-prod-*`, and alternate host ports so existing `pa-postgres` / `pa-redis` can keep running.

| Service | Host port |
|---------|-----------|
| Postgres | 5433 |
| Redis | 6380 |
| Backend | 8081 |
| Frontend | 8089 |

```bash
# From repository root — env file must define secrets (never commit them)
docker compose -p project-analytics-prod \
  -f docker/docker-compose.yml \
  -f docker/docker-compose.prod.yml \
  --env-file /path/to/prod.env \
  up -d --build
```

## Required secrets (backend fails without them)

`ProductionSecurityValidator` (`prod` profile) requires:

- `JWT_SECRET` — ≥ 32 characters, **not** the development default
- `CREDENTIALS_ENCRYPTION_KEY` — ≥ 32 characters, **distinct from** `JWT_SECRET`
- `CORS_ALLOWED_ORIGINS` — explicit origins, no `*`

Also provide `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`.

Missing or weak values must prevent backend startup. Do not bypass the validator.

Template / key list: `.env.example` (PRODUCTION section) and `docs/ops/n5.2-env-template.md`.
